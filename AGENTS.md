# AGENTS.md — ENJIGIRLING

## Цель
Поддерживать проверяемый статический инженерный справочник. Не изменять содержание, дизайн или навигацию без задачи и проверки регрессий.

## Перед изменением
1. Прочитать README.md и относящиеся к задаче документы в audit/.
2. Проверить существующие сценарии в scripts/, tests/ и .github/workflows/. Не создавать дублирующий QA.
3. Снять исходный статус и зафиксировать SHA коммита, команды и результаты.

## Обязательный контроль
- `npm run test:static` — существующий набор статических проверок; ошибки не скрывать.
- `npm run test:unit` — модульные проверки.
- `npm run test:browser` — Playwright в подготовленном окружении, если изменён интерфейс или поведение браузера.
- `npm run check:knowledge` и `npm run check:quality` — если менялись данные или их генерация.
- Для внешних URL использовать отдельный `npm run test:links`; сетевые таймауты и блокировки не считать доказанным HTTP 404.
- Для изменённых инженерных утверждений сверять первичные источники, версии документов, единицы измерения, границы применимости и риски. Тесты кода не являются научным фактчекингом.

## Запреты
- Не публиковать незаконченную инженерную академию автоматически; её выпуск — отдельное решение.
- Не подменять отсутствующие платные тексты ISO/IEC пересказом; явно помечать недоступный первоисточник.
- Не использовать Википедию.
- Не добавлять секреты, ключи или личную информацию.
- Не считать прогон, который не был выполнен, успешным. Не обходить красные тесты отключением проверок.
- Не менять русскоязычную версию сайта без отдельного запроса.

## Готовность работы
В отчёте указать: ветку и SHA; затронутые файлы; команды и exit code; количество пройденных/упавших проверок; ссылки на исходные утверждения; открытые блокеры. Если тесты нельзя запустить, указать NOT RUN и причину. До подтверждения всех применимых проверок статус BLOCKED, а не READY.
