# Матрица приёмки двух атласов: «Процессы» + «Материалы»

Версия: 2026-10-22. Контрольный снимок: 208 процессов, 172 материала, 16 отраслей. Это текущие значения, а не предел развития справочников.

**Важно:** структурный PASS не подтверждает научную достоверность. «Найден источник», «проверен частный тезис» и «проверена вся технологическая карта» — разные статусы. Последний не следует автоматически из первых двух.

## Обязательная индивидуальная проверка

- Реестр всех **380 карточек по ID**: [поимённая матрица](atlas-card-audit.md) и [структурированные замечания](../knowledge/atlas-card-audit.json).
- Запуск: `node scripts/audit-atlas-cards.cjs --write`; в CI — `node scripts/audit-atlas-cards.cjs --check`.
- Проход по каждой карточке фиксирует состояние структуры, источников, связей, ограничений и вопросы для содержательной экспертизы. **Не означает независимого подтверждения всех технических утверждений.**
- После содержательной проверки каждого утверждения требуется указать первичный документ, раздел/страницу, редакцию, область применения и исправить карточку, evidence registry и аудиторский отчёт.

## Команды

- node tests/atlas-dual-ai.cjs — единый структурный аудит данных и экспортов.
- node tests/process-atlas-data.cjs — проверка карточек процессов.
- node tests/materials-atlas-data.cjs — проверка материалов.
- node scripts/build-knowledge.cjs --check — исходники против канонических JSON.
- node scripts/build-quality.cjs --check — счётчики доказательств.
- npm run test:static — статическая матрица всего сайта.
- npm run test:browser — Chromium/Playwright на десктопе и мобильном экране.

Коды статусов: AUTO — исполняемый тест, BROWSER — тест Playwright, EDITOR — ручная работа с полным источником, LIVE — проверка опубликованной страницы. BLOCK — не принимать при провале, WARN — указывается пробел.

## Контроль разрастания кода: измеренная база и работа с долгом

**База до рефакторинга (22.10.2026):** `materials.js` — 11 486 символов; `processes.js` — 12 268; `atlas-ai-core.js` — 9 703; `atlas-ai-download.js` — 3 823. Итого **37 280 символов исполняемых модулей**. Данные отдельно: `materials-data.js` — 197 157 и `processes-data.js` — 236 468 символов. Это *объём исходного текста*, не размер скачиваемой сжатой страницы или потребление памяти.

**Выявленное дублирование:** в обеих страницах есть отдельный экспорт Markdown/JSON из собственного JS и общий экспорт Markdown/JSON/JSONL/ZIP. Форматирование, создание Blob, ссылки скачивания и обработка ошибок продублированы. Приоритет рефакторинга: один движок экспорта, общая логика сохранения, одна понятная панель на страницу; прежние кнопки убрать лишь после проверки функциональной эквивалентности и доступности.

**Автоматический бюджет:** `node tests/atlas-code-size.cjs` проверяет рост четырёх модулей относительно указанной базы (для совокупного объёма +10%; для каждого файла +20%), наличие локальных скриптов и число панелей. Превышение — сигнал об обязательном пересмотре архитектуры, а не предложение удалить полезную логику. Обновление бюджета допускается после обоснованного решения и повторного измерения, а не для обхода ошибки CI. Сами справочные данные в бюджет исполнения не включаются.

**Критерий рефакторинга:** уменьшить дублирование без потери отраслецентричной выгрузки, JSONL, ZIP, источников, статусов проверки и мобильной доступности. Сравнивать *до/после* с полным тестом 16 отраслей. Нельзя просто сокращать названия или удалять проверки ради показателя длины.

## Пробелы содержания, требующие отдельной разработки

Сейчас без подтверждённой технологической связи остаются семь материалов: water-resin, osb-board, particleboard, glulam, clt, pcb-prepreg, activated-alumina-adsorbent. Не подменять ионообмен зернистой фильтрацией, производство ДСП — производством древесноволокнистых плит, а производство препрега — монтажом платы. Сначала первичный источник о процессе, затем отдельная карточка и только потом связь.

Количества 208/172 не доказывают полноту универсального справочника. Каждая отрасль требует предметной редакционной ревизии; проверка программой подтверждает структуру, но не материалознание или безопасность изделия.

## Как дать файл модели

Для одного направления выбрать отрасль, оставить «Процессы + материалы», нажать «Markdown для чата» и прикрепить файл. Для загрузки в собственный поисковый индекс выбрать JSONL. Для всех отраслей нажать ZIP и извлечь нужные файлы (или передать ZIP модели, если она его поддерживает). Для всего атласа без дублей явно выбрать «Все отрасли».

Готовая инструкция: «Используй этот файл как редакционную инженерную базу, не как норматив. Приводи ID и ссылку источника для каждого существенного утверждения. Различай найденный источник и подтверждённый узкий тезис. Не выдумывай свойства, режимы и безопасность. Если данных не хватает, назови недостающую документацию».
