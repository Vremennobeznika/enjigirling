# Личная панель и синхронизация через Yandex Cloud

## Статус 22.10.2026

В аккаунте Yandex Cloud созданы: база `life-personal-store` (Serverless, 0 provisioned RU/s, лимит 10 RU/s, до 1 ГБ), сервисный аккаунт `life-sync-sa` с ролью `ydb.editor` **только на базе**, и пустая Cloud Function `life-sync` (`d4ed26vrlmb1uk22m3b7`). **Первая версия Cloud Function существует, но её код и настройки не соответствуют текущему проекту; синхронизация не работает.** Для исправления нужна новая версия с обновлённым deploy.zip, привязанным сервисным аккаунтом и двумя переменными окружения.

Изготовлен и проверен архив кода `deploy.zip` в ветке `life-cloud-deploy`:

Ограничение браузерной автоматизации — системный диалог выбора файла для загрузки ZIP в консоли Yandex. После ручного выбора файла нужно выбрать Node.js 22, entrypoint `index.handler`, service account `life-sync-sa`, задать переменные `YDB_CONNECTION_STRING` и `SYNC_TOKEN_SHA256`, нажать «Сохранить». Секрет синхронизации НЕ хранится в GitHub и никогда не передаётся в переменную окружения в открытом виде.

**Внимание:** переменная `YDB_CONNECTION_STRING` должна содержать `grpcs://ydb.serverless.yandexcloud.net:2135/ru-central1/b1gfjk1f2ihikvlkq67s/etnunn9vtmeospfv3c50`, а `SYNC_TOKEN_SHA256` — SHA-256 локально сохранённого случайного токена. Для этой установки SHA-256: `d218f1b19b8297372b649695b50dd046dc0947e3372fd7a5fc420c18734c58f4`. Хеш нельзя использовать вместо самого токена при синхронизации.

Таблица `app_state` автоматически создаётся серверной функцией при первом авторизованном вызове (файл `index.mjs`), поэтому вручную запускать CREATE TABLE не обязательно.


Интерфейс: https://vremennobeznika.github.io/enjigirling/life/

**Что уже работает без облака:** список задач, домашние запасы, показатели календаря и покупок, единое резервное копирование и восстановление. Существующие приложения не заменены.

**Что делает серверная функция:** сохраняет/читает в закрытой базе YDB единый JSON-снимок из четырёх разделов. Клиент использует явные кнопки «Получить из облака» / «Отправить в облако»; постоянная автосинхронизация **пока не реализована**. Не заявляйте о ней как о готовой функции.

## Настройка один раз (в аккаунте владельца)

1. В https://console.yandex.cloud/ создайте/выберите облако и каталог, подключите платёжный аккаунт. Бесплатные месячные лимиты не означают отсутствие платы при превышении.
2. В сервисе **YDB** создайте **Serverless** БД (не выделенную) и скопируйте её **строку подключения** из консоли YDB. Сохраните её как значение переменной функции `YDB_CONNECTION_STRING`.
3. В SQL-редакторе созданной БД выполните:

   ```sql
   CREATE TABLE app_state (
       id Utf8 NOT NULL,
       payload Utf8,
       revision Int64,
       PRIMARY KEY (id)
   );
   ```

   Таблица должна быть пустой. Не публикуйте её содержимое или резервные копии.
4. Создайте сервисный аккаунт `life-sync-sa` и назначьте ему роль **ydb.editor** только для созданной БД (не `editor` на всё облако).
5. Сгенерируйте **случайный уникальный секрет** (в командной строке на своём ПК, не в чате). Если у вас есть Python, запустите:

   ```bash
   python -c "import secrets,hashlib; s=secrets.token_urlsafe(48); print('TOKEN:',s); print('SHA256:',hashlib.sha256(s.encode()).hexdigest())"
   ```

   Строку `TOKEN` сохраните в менеджере паролей; **её нельзя коммитить или пересылать**. Строка `SHA256` предназначена для конфигурации функции.
6. Скачайте файлы каталога `life/cloud/` как ZIP (либо создайте архив с `index.mjs` и `package.json` в корне ZIP). В **Cloud Functions** создайте функцию `life-sync`; создайте версию:
   - Среда: **Node.js 22**.
   - Источник: ZIP с двумя файлами и зависимостями из `package.json`, если консоль не устанавливает их автоматически (при локальной сборке: `npm install --omit=dev` и включить `node_modules` в ZIP).
   - Точка входа: `index.handler`.
   - Сервисный аккаунт: `life-sync-sa`.
   - Переменные окружения: `YDB_CONNECTION_STRING` и `SYNC_TOKEN_SHA256` (именно хеш, не исходный секрет).
   - Таймаут: 15–30 секунд, память: от 256 МБ (значения примерные).
7. Разрешите HTTPS-вызов функции из браузера (публичный вызов с ограничением по секрету в коде). Скопируйте URL вида `https://functions.yandexcloud.net/<идентификатор>`.
8. Откройте https://vremennobeznika.github.io/enjigirling/life/ → **«Облачная синхронизация»**. Вставьте URL и секрет `TOKEN` **на своём устройстве**, нажмите «Применить».
9. На исходном устройстве нажмите **«Отправить в облако»**. На втором устройстве — **«Получить из облака»**. Не работайте параллельно с устаревшими копиями; сервер проверяет версию и откажет в перезаписи при конфликте.

## Финансовая безопасность

**ВАЖНО: функцию из примера нужно сделать публичной для вызовов из статического сайта.** Поэтому даже отклонённые ею запросы могут приводить к расходам на вызовы Cloud Functions. Секрет доступа защищает данные, но не защищает облачный счёт от массовых вызовов посторонними. Перед публикацией:
- Установите минимальные подходящие **квоты** Cloud Functions и YDB, ограничьте параллелизм.
- Настройте оповещения о расходах в Yandex Cloud Billing; бюджет — **оповещение, а не автоматический жёсткий лимит**: при достижении порога использование сервисов само по себе не останавливается.
- Не размещайте секрет подключения и исходные резервные копии на GitHub.
- Если управление расходами не настроено, лучше оставить всё в локальном режиме и экспортировать копии.

См. https://yandex.cloud/ru/docs/billing/concepts/budget

## Защита и ограничения

- Редактирование/чтение YDB требует сервисного аккаунта; клиентские устройства не получают ключи YDB.
- Код GitHub Pages и функция доступны публично, но данные в GitHub не выкладываются.
- Сервер проверяет случайный секрет по SHA-256 в постоянное время и разрешает CORS только для `https://vremennobeznika.github.io`. **CORS не является механизмом авторизации**; при утечке секрета его надо заменить.
- Секрет из формы находится в `sessionStorage` текущей вкладки до её закрытия; адрес URL хранится в `localStorage`.
- Функция рассчитана на **одного владельца**, не на регистрацию разных пользователей. Внешний доступ к URL функции разрешён, но GET/PUT требуют секрет. При необходимости многопользовательской работы нужна другая модель авторизации.
- Хранятся календарь, покупки, задачи, домашние запасы и журнал 72 растений. Системы финансов, врачебных данных и автоматические уведомления не реализованы.
- По умолчанию всё локально; при сбое облака данные браузера не стираются. Регулярно используйте «Скачать копию».
- Для реальной автоматической синхронизации при редактировании календаря или покупок понадобится дальнейшая интеграция отдельного общего sync-клиента в эти страницы.
- Развёртывание и работа функции **ещё не были проверены на реальном аккаунте Yandex Cloud**. Перед хранением значимых данных протестируйте создание таблицы, авторизацию, чтение/запись и отказ при конфликте версий.
- Сервис Yandex Cloud может стать платным при превышении бесплатных лимитов.
