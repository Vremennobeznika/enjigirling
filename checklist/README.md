# Общий список дел: Ева · Дима · Кася

Внутри — один самостоятельный HTML, работающий на GitHub Pages. Дела и этапы, галочки, три вкладки, импорт/экспорт JSON. Для общей синхронизации используется Supabase (без отдельного сервера Yandex Cloud).

## Состояние

Клиент готов и протестирован с имитатором Supabase RPC на двух виртуальных устройствах. **К реальному проекту Supabase пока не подключён**: доступ к аккаунту в этой сессии отсутствует, URL проекта и его publishable key не получены, SQL не выполнялся в реальной базе. До настройки облака списки работают локально.

## Одноразовая настройка

1. Создать проект в [Supabase](https://supabase.com/dashboard) или подключить Supabase к ChatGPT с доступом к проекту.
2. Открыть `https://vremennobeznika.github.io/enjigirling/checklist/`, нажать «Создать семейный ключ». Сохранить сам ключ отдельно. Скопировать SHA-256, показанный ниже.
3. В Supabase → **SQL Editor** открыть файл `schema.sql`, заменить **только** `REPLACE_WITH_64_HEX_SHA256` на полученный SHA-256 (64 символа), выполнить скрипт один раз. **Не передавать сам семейный ключ в SQL**.
4. В Supabase → Connect / Settings → API получить **Project URL** и **Publishable key** (`sb_publishable_...`). Не брать `sb_secret_...` или `service_role`.
5. На странице списка в разделе «Общий доступ» заполнить адрес проекта, publishable key и семейный ключ, нажать «Подключить». Проверить статус «Синхронизировано».
6. На втором телефоне открыть **ту же ссылку** и ввести те же три значения, нажать «Подключить». Если там уже есть отдельные дела, прежде сохраните их в JSON: первые два набора данных могут потребовать ручного объединения, чтобы не стереть записи.

После первого подключения URL и публичный ключ можно прописать в `SUPABASE_DEFAULT_URL` и `SUPABASE_DEFAULT_PUBLIC_KEY` HTML (это **не секреты**), чтобы на новых телефонах вводить только семейный ключ.

### Безопасность и поведение

- База содержит только семейные списки. Данные прежнего личного приложения `life/` не используются.
- На таблице включена RLS и отозваны прямые права для `anon` и `authenticated`. Доступ к данным возможен через две ограниченные RPC (`get`/`put`) при предъявлении длинного случайного семейного ключа, проверяемого по SHA-256.
- Запись использует проверку ревизии (CAS). Независимые одновременные изменения объединяются клиентом; противоречащие изменения требуют выбора, без скрытого перезаписывания.
- Синхронизация при изменениях и примерно каждые 8 секунд при открытой странице. При закрытой странице — после повторного открытия; в офлайне — позже. Это **не** мгновенный push-режим.
- Семейный ключ сохраняется в localStorage телефона: он не должен попадать в URL, GitHub, публичные скриншоты. Доступ к профилю браузера означает доступ к ключу.
- Публичный publishable key Supabase предназначен для клиентских приложений. Секретный `sb_secret` в HTML категорически запрещён.
- При утечке семейного ключа нужно сменить его и обновить `access_hash` в БД; это разорвёт доступ старых устройств. Смена проводится администратором базы.
- Данные Supabase могут быть доступны его оператору в рамках условий сервиса. Не храните в приложении пароли, медицинские или другие секретные сведения.
- Бесплатный проект может останавливаться из-за неактивности; проверьте актуальные условия Supabase.
