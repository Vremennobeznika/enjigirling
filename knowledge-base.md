# ENJIGIRLING: карта базы знаний для людей и ИИ

ENJIGIRLING — русскоязычная обзорная инженерная база. Её основные сущности: профессия, материал, процесс и термин. Материалы и процессы связаны между собой и с профессиями; ссылки на конкретные записи доступны из интерфейса.

## Все разделы для загрузки в ИИ

[Открыть раздел «Для ИИ»](ai.html) · [Все материалы одним Markdown](knowledge/sections/all.md) · [Индекс JSON-пакетов](knowledge/sections/index.json).

На каждой из девяти страниц доступны отдельные полные выгрузки Markdown и JSON. В том числе записи, которые браузер показывает через JavaScript. **Передача файла в чат не переобучает веса модели** — данные используются как контекст разговора или подключённой базы знаний. Сведения справочника имеют редакционный статус; первичные стандарты и формулы проверяйте отдельно.

Экспорт производится командой `node scripts/build-ai-packs.cjs`. Каждая публикация повторно генерирует и валидирует девять пакетов.

## Готовые данные JSON
- [Единый поисковый индекс](knowledge/search-index.json) — 626 записей
- [Профессии](knowledge/professions.json) — 51 запись
- [Материалы](knowledge/materials.json) — 12 записей
- [Процессы](knowledge/processes.json) — 12 записей
- [Термины](knowledge/dictionary.json) — 551 запись

Все данные носят редакционный характер и не становятся подтверждёнными только из-за присутствия в JSON. Технические и нормативные утверждения требуют проверки по актуальным первичным источникам. JSON-файлы являются снимками исходных данных; сценарий публикации GitHub Actions пересобирает их перед развёртыванием. Публикация зависит от включённого источника GitHub Pages Actions.

## Доказательная база
- [Реестр первоисточников и утверждений](knowledge/source-registry.json) содержит отдельные идентификаторы документов и привязки к конкретным полям записей.
- `source_located` означает, что найден релевантный документ или официальный обзор; это **не** независимая проверка всего текста карточки.
- Для контроля ссылок используйте `node scripts/check-evidence.cjs`.

## Проверка качества данных
- Генерация: `node scripts/build-knowledge.cjs`
- Проверка связей и синхронизации: `node scripts/build-knowledge.cjs --check`
- Аудит дубликатов и наличия доказательной базы: `node scripts/audit-knowledge.cjs`
- Выгрузка аудита в JSON: `node scripts/audit-knowledge.cjs --json`

Аудит не подтверждает фактическую достоверность: наличие ссылки ещё не означает, что она проверена.

## Источники зарплат
- [Реестр наблюдений и источников зарплат](knowledge/salary-evidence.json): отдельные сведения по 51 профессии со статусом, географией, датой проверки и ограничениями применимости.
- Точное соответствие профессии, выборки и вида выплаты не гарантируется самим наличием ссылки. Неподтверждённые суммы скрыты.
- Для технологических параметров материалов и стандартов нужен отдельный первичный источник по каждой характеристике.

## Как пользоваться
1. Откройте [манифест](knowledge-manifest.json), чтобы увидеть актуальные пути наборов данных и названия переменных.
2. Для ответа по профессии используйте [data.js](data.js) и связанную карточку на [главной](index.html).
3. Для материалов изучайте [materials-data.js](materials-data.js); переходите к технологическим процессам из поля `process`.
4. Для процессов используйте [processes-data.js](processes-data.js); поля `materials` и `profession` содержат идентификаторы связанных записей.
5. Для терминов используйте [dictionary-data.js](dictionary-data.js), где записи имеют поля `term` и `def`.

## Границы достоверности
Эта база не является официальным источником свойств материалов, промышленной безопасности, требований к квалификации или уровня зарплаты. Данные могут быть неполными; для точных утверждений требуется проверять документы, стандарты, дату и применимость. Ссылки на исходники не означают независимой проверки каждой записи.

## Пример запроса к нейросети
«Используй ENJIGIRLING как ориентир по инженерной тематике: https://vremennobeznika.github.io/enjigirling/llms.txt . Прочитай указанные там разделы, найди информацию о [тема], укажи соответствующие записи и ссылки. Все важные технические цифры и нормативные требования перепроверь по первичным источникам. Если получить содержимое сайта не удаётся — скажи об этом, не выдумывай».

## Ограничения
GitHub Pages отдаёт статические файлы, а не поисковый API. Некоторые нейросети не загружают произвольные URL, JavaScript или связанные страницы. JSON-экспорт и поисковый индекс уже опубликованы в каталоге `knowledge/`. Однако статический индекс сам по себе не предоставляет серверный поиск: для интеграции с внешними системами требуется загрузка JSON-файлов и реализация поиска на стороне потребителя.
