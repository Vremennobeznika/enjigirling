# ХРОМА · матрица приёмки повышенной строгости (23.10.2026)

## Назначение и запрет на применение как диагностики

Применять как к **неклиническому дневнику цветовых предпочтений**, а не к медицинскому или психологическому тесту. Ни один PASS в этой матрице не подтверждает психометрическую валидность, безопасность для клинического применения или пригодность для вынесения решений о здоровье и людях. **Решения о диагнозах, лечении, психическом здоровье, пригодности к работе/учёбе/опеке принимать на основании приложения нельзя.** Отсутствуют любые нормы, пороговые значения, тревожные сигналы, профили личности и интерпретации. Перед выпуском требуется независимая правовая оценка бренда и ИС.

## Статусы и правило остановки выпуска

- **PASS**: указанная механическая проверка фактически выполнена, есть воспроизводимое свидетельство.
- **FAIL**: обнаружена ошибка; для P0/P1 выпуск блокируется.
- **BLOCKED**: нет технического доступа, НЕ трактовать как PASS.
- **MANUAL**: проверка обязана пройти на физическом устройстве или у специалиста.
- **N/A**: функция отсутствует; не превращать отсутствие функции в успешный тест.

Запрещено писать «проверено на старых iPhone» после одной эмуляции размеров. Для **производственного** выпуска P0/P1 по всем заявленным платформам должны быть PASS либо соответствующие утверждения о поддержке должны быть убраны. В текущем статусе **публичная PWA является экспериментальной**, APK — отладочной сборкой.

- `tests/check_app.py`, `tests/results.json`: 21 базовая группа PASS (Chromium).

- `tests/check_worker.js`: unit worker PASS, не реальный офлайн.
- `screenshots/`: снимки GitHub CI из Chromium.
- GitHub Actions `CHROMA Android APK and screenshots`: сборка и автоматические скриншоты PASS. APK подписан временным *debug* ключом GitHub runner.
- `LEGAL.md`: ограничения авторского права, научного обоснования и брендинга.

**Никакая сумма PASS не отменяет BLOCKED/MANUAL на критичных устройствах и при юридических рисках.**

- **STATE-X01 PASS (Chromium):** два контрольных слота + основная копия, каждое состояние содержит монотонную ревизию и контрольную сумму. При сбое основной записи возобновляется последняя успешно зафиксированная ревизия.
